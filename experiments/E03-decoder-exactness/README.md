# E03 — Stage 2 解码器的精确性

**状态**: 已完成, PASS (召回 100% / 精确率 100% / 假阳性 0 / 方向 100%)
**耗时**: ~20 s (加载 13 s + design 0.28 s + de_table 4 s), 固定种子, 完全确定

## 目的

Stage 2 的契约: 给它一个「意图」(哪些基因响应 + 每个基因的目标 lfc), 它必须交出
**400 个整数细胞**, 使官方口径的 DE 在这 400 个细胞上恰好复现这个意图 ——
一个不多, 一个不少, 方向不错.

只要这个契约成立, 建模问题就完全收缩成 Stage 1 (预测响应集与方向), 打分器的
构造细节 (稀疏度、库大小、过散、并列) 全部不用再管. 本实验是这个契约的冲烟测试.

## 方法

意图 (`default_rng(42)`): 从 gate 内 9,929 个基因里随机取 **250** 个,
每个配一个随机方向、`|lfc| ~ U(0.4, 2.2)` 的目标 lfc.

构造 (`ControlRef.design(..., seed=1)`) 的三个要点:

1. **null 背景用真实对照细胞自举** -> `psi_bar` 自动落在 0.5 附近, 稀疏度与
   过散天然正确, 不需要拟合任何分布;
2. **CPM 是成分数据**: 目标 profile 的列均值之和必须重归一到 1e6, 否则每细胞
   的行和无解 (`design` 会抛 ValueError);
3. **响应基因用两点分布** (E02 的旋钮), 对非零比例二分, 使 `psi_bar` 命中
   `0.5 ± 0.10` —— 显著性与方向就此解耦.

然后用最大余数法 (Hamilton) 逐行补平到**恰好 1e6**, 于是 `counts == CPM`,
打分器的归一化成为恒等映射. 三个硬约束在脚本里是 `assert`: 非负 / 整数 / 行和 1e6.

判据: `ControlRef.de_table` (= 官方 DE 的精确复刻, E04 已逐基因验证) 的
`p_adj < 0.05` 集合 R̂ 与意图集 R 比对.

## 实测结果

见 `RESULT.md`. 意图 250 -> 实际 250, 命中 250, 召回 100.0%, 精确率 100.0%,
**假阳性 0**, 方向一致率 100.0%, nnz/cell = 5,998.

## 结论

1. Stage 2 是**无损**的: 意图与实现之间没有信息丢失, 也没有溢出的假阳性.
   全部剩余误差都在 Stage 1 —— 这是一个干净的问题边界.
2. 「预测什么都没变」不能靠交出对照均值的复制品: 400 个完全相同的细胞是
   E02 里 `t = 0` 的极端, 会把大量基因判成显著 (解码器故障, 不是选集故障).
   `design` 的自举背景就是为了避免这一点.
3. 单核 `de_table` 约 4 s/组 -> 900 个 (pert, context) 约 60 min 单核 /
   6 min 十核, 完全可以把「提交前自评」放进迭代循环 (官方全 panel 需 52 h).
4. 完美 Stage 1 假设下的理论上限 (2026-08-27 记录): `jac_raw = 1.0` -> scaled
   2.62, `fid_raw = 1.0` -> scaled 1.62, `nmae` -> scaled 1.66.
